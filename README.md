# ldnmp-sitebak

`ldnmp-sitebak` 是一个面向 LDNMP/科技 LION 常见服务器结构的 WordPress 单站点备份恢复脚本。

它的目标很简单：当一台 VPS 上有多个 WordPress 站点时，不再只能把整个 `/home/web` 全站打成一个包，而是可以按域名单独备份、单独恢复。

## 功能

- 纯交互菜单，输入 `kk` 即可使用。
- 单独备份某个 WordPress 站点。
- 同一站点多个备份版本可按编号选择恢复。
- 菜单 `4` 每次实时扫描当前 WordPress 站点；选定域名后，只显示该域名的普通备份版本。
- 备份包自带时间戳，例如 `example.com_20260912_153000.tar.gz`。
- 自动备份站点文件、数据库、Nginx 配置、SSL 证书和恢复清单。
- 恢复前二次确认，并可自动创建当前站点快照。
- 完整快照包含站点文件、数据库、Nginx 配置和证书，菜单 `5` 可创建、查看、恢复和删除快照。
- 普通备份与快照分别管理：菜单 `3/4/6` 只查看、恢复、删除普通备份，快照统一进入菜单 `5`。
- 固定五行 LDNMP 字符 Banner，中文副标题上下使用同宽分隔线；采用亮青蓝主色、黄色编号、草绿色标签和浅草绿色版本与目录信息，以及绿/红/黄状态提示。
- 支持从 GitHub 更新本地脚本。
- 菜单 `8` 提供独立的站点导入入口；v0.4.1 在安全导入文件和数据库后，使用与 WP Box 相同的固定 WP-CLI Docker 镜像完成域名替换、Elementor 修复和 WordPress 收尾，并按实际完成节点显示总体进度。

## 首次安装

```bash
bash <(curl -fsSL "https://raw.githubusercontent.com/hajimi2024/ldnmp-sitebak/main/install.sh?sitebak_nocache=$(date +%s)" || printf 'exit 1\n')
```

在 Linux VPS 的 root 终端执行。安装器会以加粗黄色明确显示成功或失败，并与上方输出隔开；校验或安装失败时保留已安装的脚本。若最前面的安装器下载失败，`curl` 会直接报错并返回非零状态。

## 使用

进入交互菜单：

```bash
kk
```

快捷备份：

```bash
kk backup example.com
```

恢复指定站点，并从备份列表中选择版本：

```bash
kk restore example.com
```

直接恢复指定备份包：

```bash
kk restore /home/example.com_20260912_153000.tar.gz
```

更新脚本：

```bash
kk update
```

进入站点导入菜单：

```bash
kk migrate
```

当前 v0.4.1 的站点导入会让用户选择普通备份和已预建的空白目标站点（可输入编号或列表中的完整域名），检查归档安全、WordPress Root、目标数据库空库状态和同一 `server` 块内的 Nginx 协议，并在受限临时目录中验证文件映射。确认前会检查或拉取与 WP Box 相同的固定摘要 WP-CLI 镜像，通过 `web_default` 网络验证一次性容器和目标数据库连接。镜像长期缓存；每次命令使用 `docker run --rm`、目标 Root 的非 root 属主及仅限目标 Root 的挂载，并显式执行镜像内的 `wp` 命令。更换域名模式对 HTTP、HTTPS、协议相对 URL 和有域名边界的裸域名依次 dry-run 后正式替换，始终跳过 GUID；随后按实际安装状态处理 Elementor、刷新固定链接并验证 `home`、`siteurl`、数据库连接和表前缀。总体进度条只在安全检查、解压、暂存、导入、文件替换和 WordPress 收尾等节点实际完成后前进，全部成功后才显示 100%。只允许从空白目标站点完整导入；写入后失败时需重新准备空站点，从头执行。全过程不修改 Nginx、SSL 或共享容器配置，也不重启共享服务。完整安全边界见 [站点导入安全设计](docs/MIGRATION.md)。

交互菜单选择 `7. 更新脚本` 后会绕过 GitHub Raw 缓存下载、校验并安全替换脚本，成功后自动载入新版菜单。

## 默认路径

站点识别支持 `/home/web/html/域名/wp-config.php` 和 LDNMP 常用的
`/home/web/html/域名/wordpress/wp-config.php`。备份仍打包整个域名目录，保留原目录结构。
若同一域名两处都存在配置，脚本不会自动选择，以免选错数据库。

```bash
站点目录：/home/web/html
备份目录：/home
快照目录：/home  -  备注：snapshot
Nginx 配置：/home/web/conf.d
SSL 证书：/home/web/certs
```

如需覆盖默认路径，可以使用环境变量：

```bash
SITEBAK_BACKUP_DIR=/root/backups kk backup example.com
```

## 备份包结构

单站备份完成后，服务器默认只保存一个完整压缩包：

```text
/home/<域名>_<YYYYMMDD>_<HHMMSS>.tar.gz
```

上面的 `.tar.gz` 是外层备份包，以下七项是它内部的目录和文件：

```text
<域名>_<YYYYMMDD>_<HHMMSS>.tar.gz
└── 解压后
    ├── files/site-files.tar.gz
    ├── database/数据库名.sql.gz
    ├── nginx/nginx-files.tar.gz
    ├── certs/cert-items.tar.gz
    ├── meta/
    ├── manifest.json
    └── restore-notes.txt
```

默认备份目录是 `/home`；如使用 `SITEBAK_BACKUP_DIR` 覆盖，压缩包会保存到指定目录。内部临时文件不会作为独立备份文件长期保留。

- v0.4.0：站点导入形成完整闭环，并统一为 WP Box 固定摘要的 WP-CLI 一次性容器。复用或拉取缓存镜像，只挂载目标 WordPress Root；在空白目标数据库完成文件和数据导入后，执行序列化安全的精确域名替换、Elementor URL/CSS 修复、固定链接与瞬态缓存刷新及最终配置校验。
- v0.3.9：优化站点导入交互和运行反馈：目标站点可按编号或列表内域名选择；归档检查、暂存、数据库导入和文件替换均显示状态；确认输入错误可重试；确认单仅显示主机名、CPU 与内存，不暴露登录用户和机器身份摘要。
- v0.3.8：站点导入阶段三完成。确认后将普通备份的 WordPress Root 写入指定目标 Root，并把 SQL 导入已确认的空目标数据库；导入前后记录明确状态并清理临时目录。更换域名模式尚不执行旧网址替换，Nginx、SSL 和共享容器不受本阶段影响。

- v0.3.7：站点导入预检按单个目标域名 `server` 块判断 HTTPS，拒绝符号链接链、重复归档成员和链接覆盖路径；加入服务器、WordPress Root、数据库连接、数据库名称及表前缀组成的目标身份锁，身份或范围变化立即停止。本阶段仍不执行正式导入。

- v0.3.6：站点导入进入只读预检和临时暂存阶段；只接受普通备份，只允许选择实际发现的目标站点，拒绝非空数据库、异常归档路径、特殊文件和逃逸链接，并验证目标数据库配置及 Nginx 协议。本阶段仍不执行正式导入。

- v0.3.5：主菜单新增独立的 `8. 站点导入 ♻️` 区域和 `kk migrate` 入口，建立权限受限、过滤敏感信息的操作日志框架；本阶段不执行文件或数据库导入。

- v0.3.3：首页 GitHub 网址改为与 LDNMP 标题同色系的细体亮蓝色，黄色标签、可点击链接和无下划线保持不变。

- v0.1.6：修复恢复后统一更改文件归属的问题，按备份保留每个站点文件的数字 UID/GID 和权限；兼容旧版备份。通过真实 Linux 文件权限测试，数据库和服务调用使用模拟命令。

- v0.1.5：检测客户端支持情况，关闭单站备份中的服务器级脱敏策略导出，避免普通站点账号触发 `column_masking_policy` 权限错误；导出工具即使返回成功码，若仍报告错误也会停止打包。此模式不适用于依赖数据库脱敏策略的站点。

- v0.1.4：支持 LDNMP 的数据库容器，宿主机无需单独安装 `mysqldump`；兼容容器内 MySQL/MariaDB 导出与导入工具。数据库导出失败不会生成备份包，恢复前先检查客户端和数据库连接。
- 自动匹配 `DB_HOST` 同名的 Docker 容器（LDNMP 通常为 `mysql`）。容器自定义名称与 `DB_HOST` 不一致时，可使用 `SITEBAK_DB_CONTAINER=容器名 kk`；不使用容器的站点继续使用宿主机客户端。
- 数据库兼容性已通过模拟 Docker/数据库命令的回归测试，包含实际文件打包和恢复；尚未在真实数据库服务器上完成端到端验证。

- v0.1.3：菜单操作失败后保留错误信息，输入 `0` 返回上一级；更新下载或校验失败时保留原脚本。

- v0.1.1 修复 LDNMP 的 `wordpress` 子目录识别、空站点列表和标题边框对齐。
- 本地回归测试覆盖站点识别、数据库配置读取、菜单输出及边框宽度；尚未完成真实 VPS 的备份恢复验证。

- 推荐在同样的 LDNMP 环境中恢复。
- 同域名恢复通常不需要额外修改 WordPress 设置。
- 如果更换域名，当前版本不会自动执行 WordPress 数据库 `search-replace`。
- 商业插件的文件、设置和数据库中的 license key 通常会被备份，但远程激活状态是否保持取决于插件厂商。
