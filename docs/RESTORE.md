# 恢复说明

## 推荐环境

推荐在同样的 LDNMP/科技 LION 环境中恢复，尤其是目录结构一致时，恢复成功率最高。

默认目标路径：

```bash
/home/web/html/域名
```

## 恢复流程

从交互菜单选择 `4. 恢复单个站点` 后，脚本会先实时扫描当前站点目录并列出 WordPress 域名。选定域名后，才会按编号显示该域名的普通备份版本，不会混入其他站点的备份。若该域名没有普通备份，会提示“当前域名无可用备份”，可输入 `0` 返回站点选择页。

执行：

```bash
kk restore example.com
```

脚本会列出该域名的备份版本：

```text
1. example.com_20260912_153000.tar.gz
2. example.com_20260910_020000.tar.gz
0. 返回上一级
```

选择编号后，脚本会要求输入 `yes` 二次确认。

如果当前站点目录已存在，脚本会询问是否创建当前状态快照。建议保留默认选择。

v0.2.0 起，该快照包含当前站点的文件、数据库、Nginx 配置、证书及恢复清单。
文件名为 `域名_snapshot_年月日_时分秒.tar.gz`。创建失败会停止后续覆盖操作；
输入 `n` 可明确跳过，输入 `0` 可取消恢复。
快照需能找到对应 Nginx 配置；HTTPS 站点还需找到证书。配置或证书打包失败不能标为完整快照。

需要回退时，在主菜单进入 `5. 快照管理`，选择 `3. 恢复完整快照`，按编号选择版本。
这会恢复该快照中的文件、导入数据库、恢复配置和证书。恢复前同样可保留当前状态的完整快照。
旧版 `before_restore` 文件不含数据库和恢复清单，不能用于此操作；脚本不会把它们改名伪装成完整快照。

## 恢复内容

- 站点文件。
- 数据库。
- Nginx 配置。
- SSL 证书。
- 按备份记录恢复每个站点文件和目录的数字 UID/GID 及权限，不统一修改为固定用户。
- 服务重载或重启。

## 重要限制

- 快照是单站点在线备份，不是整台 VPS 的磁盘快照。它不包含共用容器镜像、数据库用户重建或服务器基础配置。
- 文件和数据库不是同一瞬间冻结。交易活跃的商城需要另行安排维护窗口或暂停写入，以取得严格一致的恢复点。

- v0.1.6 修复恢复时强制改成 `1000:1000` 的缺陷。旧版备份中的所有者信息仍可读取，不需要为此重新备份。
- 恢复需使用 root。目标环境中 PHP 进程的 UID/GID 应与备份时一致；跨环境用户编号不一致时需要先核对，脚本不会猜测或自动改写。

- 当前版本主要面向同域名恢复。
- 如果更换域名，WordPress 数据库中的链接、序列化数据、插件配置需要额外处理。
- 商业插件的远程授权状态不保证恢复，具体取决于插件厂商。
