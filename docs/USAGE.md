# 使用说明

## 交互模式

运行：

```bash
kk
```

菜单：

```text
操作
------------------------
1.  列出 WordPress 站点                 2.  备份单个站点

3.  查看备份文件                        4.  恢复单个站点

5.  快照管理                            6.  删除旧备份

7.  更新脚本

8.  站点导入 ♻️
------------------------
0.  退出
------------------------
```

主菜单输入 `0` 退出，子菜单输入 `0` 返回上一级。输错编号或域名格式错误时，脚本会提示并停留在当前流程。

选择 `7. 更新脚本` 后，脚本会绕过 GitHub Raw 缓存下载并校验新版；替换成功后自动重新载入新版菜单。更新失败时保留原脚本并返回当前菜单。

主菜单输入 `8` 或执行 `kk migrate` 可进入站点导入菜单。v0.6.1 会先验证选定目标数据库为零张表；检测到任何表或无法检查时立即停止。目标站点可输入编号，或直接输入当前列表中的完整域名；使用编号时还需再次输入完整域名确认，直接输入域名不重复确认。通过空库检查和最终确认后，才会写入目标 WordPress Root 和目标数据库并执行 WordPress 收尾。交互终端使用 Bash Readline 处理中文宽字符输入，避免退格时覆盖提示文本。

首页会动态显示当前服务器标签，格式为 `当前服务器：@主机名 CPUc内存g`；其中主机名、CPU 核数和内存容量均从当前 VPS 实时读取。

选择“导入并保留域名”时，备份选择界面会显示“适用于跨服务器导入并保留域名”，用于区分该模式与当前服务器内的站点还原。

选择“导入并更换域名”时，备份选择界面会显示“适用于跨服务器导入并更换域名”。

```text
站点导入
------------------------
1.  导入并更换域名             2.  导入并保留域名

3.  查看最近一次操作日志
------------------------
0.  返回上一级
------------------------
```

站点导入流程只列出普通备份，不接受快照或旧版 `before_restore` 文件。目标站点必须已经存在于当前站点列表中，不能临时输入任意域名；导入并更换域名要求源、目标域名不同，导入并保留域名要求两者一致。

阶段二会验证归档结构和路径安全、唯一 WordPress Root、四项数据库配置、目标数据库为空以及同一目标域名 `server` 块内的 Nginx HTTP/HTTPS 配置。重复归档成员、符号链接链、链接父路径写入及后续成员覆盖均会被拒绝。源 WordPress 文件只映射到目标 WordPress Root 的临时副本，目标 Root 外的文件、Nginx 和 SSL 不会被修改。临时目录在成功、失败或取消后都会清理。

目标身份由目标域名、当前服务器身份、WordPress Root、数据库连接、数据库名称和表前缀共同确定；还会锁定配置文件、目录和 Nginx 配置指纹。暂存完成后会显示最终确认单（主机名、CPU 和内存仅用于展示，机器身份锁仍在后台复核），只有输入完整小写 `yes` 才会继续；错误内容会留在确认环节重试，直接回车取消，输入 `0` 返回上一级。数据库导入前要求空库并重新验证完整身份；数据库写入后、文件替换前改为复核目标范围和连接。更换域名模式使用 WP-CLI 对四类旧域名表示依次 dry-run 和正式替换，始终使用 `--all-tables-with-prefix --skip-columns=guid --precise`；保留域名模式跳过全库替换。Elementor 仅在已安装并启用且实际注册 `replace_urls`、`flush_css` 命令时处理，不自动安装、升级或启用插件。导入只写入目标 WordPress Root 与目标数据库，不修改 Nginx、SSL 或共享容器。

WP-CLI 使用与 WP Box 相同的固定摘要镜像和 `web_default` Docker 网络。镜像不存在时在确认前拉取并缓存；每次命令以目标 Root 属主在 `docker run --rm` 一次性容器中运行，只挂载已验证的目标 WordPress Root，并显式调用镜像中的 `wp`，不使用共享 PHP 容器或临时 PHAR。写入后失败时需重新准备空白目标站点并从头导入。

站点导入显示 0%–100% 总体进度条。百分比只在对应安全检查、解压、暂存、数据库导入、文件替换、域名处理、Elementor 和最终校验实际完成后增加；无法可靠统计内部处理量的命令不会按时间估算。交互终端原地刷新，窄终端缩短进度条，无色或非交互环境使用纯文本。失败时保留当前实际进度，只有完整导入及 WordPress 收尾成功后显示 100%。

操作日志默认保存在 `/home/sitebak-logs`；目录权限为 `0700`，文件权限为 `0600`，写入前会过滤常见密码、令牌和连接字符串凭据。日志文件名包含时间、操作类型、源域名和目标域名；旧 `/var/log/sitebak` 日志仍可读取。菜单 `3` 可查看最近一次操作日志；“预检通过”不代表网站已经导入。

所有交互菜单统一使用分隔线区分标题、正文和返回区域。`0.  返回上一级`（主菜单为 `0.  退出`）上下各有一条分隔线。主菜单和快照管理的每组操作之间保留一行空白；终端少于 58 列时自动改为单列，窗口变宽后恢复双列。

菜单 `3` 只查看普通备份；菜单 `4` 每次先实时扫描当前 WordPress 站点，按编号选择域名后，只显示该域名的普通备份版本供恢复；菜单 `6` 只选择删除普通备份。
若所选域名没有普通备份，脚本会提示“当前域名无可用备份”，输入 `0` 返回上一级。
完整快照和旧版文件快照统一在菜单 `5` 管理，不会出现在普通备份的查看、恢复或删除列表里。
“删除旧备份”是手动选择一个普通备份并确认删除，不会按文件年龄自动清理。

## 界面配色

保留五行细线 LDNMP 字符 Banner，中文副标题上下各使用一条 38 列青色分界线。
终端少于 38 列时显示紧凑标题，中文副标题上下各使用一条 16 列分界线，不截断字符字形。

| 内容 | 配色 |
| --- | --- |
| Banner、标题 | 加粗亮青蓝 |
| 菜单文字、文件名、路径、普通提示 | 亮青蓝 |
| 菜单和选择列表编号 | 加粗黄色 |
| 编号、域名、确认值等输入提示文字 | 加粗亮青蓝 |
| 光标后由用户输入的内容 | 加粗黄色 |
| 版本、站点目录、备份目录、快照目录四行 | 加粗黄色标签，浅草绿色值 |
| GitHub 地址 | 加粗黄色标签、细体亮蓝色链接 |
| Banner 分界线、中文副标题 | 加粗亮青蓝 |
| 成功 / 错误 / 警告 | 绿色 / 红色 / 黄色 |

颜色使用终端 ANSI 色，不设置终端字号；实际色调由终端配色方案决定。
设置 `NO_COLOR`、使用 `TERM=dumb` 或标准输出与错误输出均未连接终端时，自动使用无颜色文本。
首页 GitHub 地址使用 OSC 8 终端超链接并显式关闭下划线；终端不支持时仍显示完整 URL，可直接复制访问。

```bash
NO_COLOR=1 kk
```

## 快照管理

主菜单输入 `5`：

```text
快照管理
------------------------
1.  创建完整快照             2.  查看快照

3.  恢复完整快照             4.  删除快照
------------------------
0.  返回上一级
------------------------
```

完整快照采用 `域名_snapshot_年月日_时分秒.tar.gz` 命名，默认位于 `/home`。
包含站点文件、数据库、对应 Nginx 配置和证书，并记录原始文件权限。
创建快照只读取当前站点，不执行恢复。

恢复列表列出各域名的完整快照、文件大小及时间，按编号选择后输入 `yes` 确认。
即使站点目录已经不存在，也可以从列表中恢复。
恢复前默认创建当前站点的完整快照；创建失败就停止，不继续覆盖。
恢复快照时也采用同样的保护流程，不会递归执行恢复。

查看和删除列表会标注旧版 `before_restore` 文件；它们不能出现在完整快照恢复列表中。
删除需要输入 `yes` 确认。同一秒出现同名快照时会拒绝覆盖，请稍后重试。

快捷命令：

```bash
kk snapshot example.com
kk list-snapshots example.com
kk restore-snapshot example.com
kk restore-snapshot /home/example.com_snapshot_20260912_163233.tar.gz
```

`kk list-backups` 和菜单“查看备份文件”都只列普通备份；`kk list-snapshots` 和快照管理内的“查看快照”列出完整快照、旧版文件快照，并区分类型。

## 命令行模式

进入站点导入菜单：

```bash
kk migrate
```

列出站点：

```bash
kk list
```

备份站点：

```bash
kk backup example.com
```

列出备份：

```bash
kk list-backups
kk list-backups example.com
```

恢复站点：

```bash
kk restore example.com
```

恢复指定压缩包：

```bash
kk restore /home/example.com_20260912_153000.tar.gz
```

## 备份文件名

备份文件会默认保存在 `/home`：

```text
example.com_20260912_153000.tar.gz
```

格式是：

```text
域名_年月日_时分秒.tar.gz
```
