# 站点导入安全设计

## 最高原则

任何站点导入操作都必须严格限定在用户指定的目标网站。宁可拒绝导入，也不能污染同一台服务器或其他服务器上的正常网站。

当前 v0.4.3 已形成一次性完整导入流程：安全导入文件和数据库后，使用与 WP Box 相同的固定摘要 WP-CLI 一次性 Docker 容器显式执行 `wp`，完成域名替换、Elementor 修复、固定链接和瞬态缓存刷新及最终校验。仍不修改 Nginx 和 SSL，也不重启共享容器。

## 目标身份

迁移目标不能只用域名或目录名识别。SiteBak 使用以下信息共同建立目标身份：

- 目标域名；
- 当前目标服务器的主机名和 `machine-id` 摘要；
- 经过 `realpath` 解析的 WordPress Root、目录设备号、inode 和属主；
- `wp-config.php` 的真实路径和内容摘要；
- 数据库容器或主机、连接参数及数据库用户；
- 目标数据库名称；
- 目标站原表前缀和迁入站点表前缀；
- 目标域名 Nginx 配置摘要及最终协议。

阶段二在目标空库检查后锁定上述身份，在临时暂存完成后重新发现目标并再次验证。最终确认后、数据库导入前再次验证完整身份与备份指纹。数据库导入后目标库不再为空，因此文件替换前改为复核同一目标身份的服务器、路径、配置、连接、数据库名、表前缀、Nginx 和协议，而不将正常导入后的表视为异常。

同一域名可以同时存在于旧生产 VPS 和新目标 VPS。服务器身份是目标身份的必要部分；后续正式执行前必须把目标服务器身份显示给用户，且身份必须与预检时完全一致，不能仅凭相同域名继续。

## Nginx 协议判断

每个匹配目标域名的有效 `server` 块独立检查，不跨块合并指令。HTTPS 块必须在同一个块内同时具备：

- 443 监听；
- 该 443 监听上的 `ssl` 参数；
- `ssl_certificate`；
- `ssl_certificate_key`。

目标域名只要存在不完整或冲突的 TLS 块，就拒绝迁移。其他域名或相似域名的配置不能为目标域名补齐条件。

## 归档和暂存边界

归档在解压前完成成员级检查：拒绝绝对路径、`..` 越界、设备和管道、硬链接、重复规范化路径、符号链接父路径写入，以及后续成员覆盖已使用父路径。允许的符号链接也必须是相对且不含越界成分；解压后再次确认其真实目标仍位于临时目录内。

解压目标必须是本次创建的空目录。临时文件只存在于权限受限的迁移临时目录，成功、失败或取消后均清理；原始备份和迁移日志保留。

## 正式写入前的强制检查点

正式写入时，必须在以下每个动作之前重新验证目标身份与操作范围：

1. 正式导入数据库；
2. 将暂存文件切换到正式 WordPress Root；
3. 运行 WP-CLI；
4. 运行 Elementor 命令。

发现配置变化、路径变化、数据库变化、服务器变化或身份指纹不一致时立即停止，不自动重试。

数据库导入只能连接已确认的目标数据库，拒绝 `CREATE DATABASE`、`DROP DATABASE` 和 `USE` 语句，且不创建数据库。文件写入只能发生在经过验证的目标 WordPress Root 内，不能触及域名目录的其他文件，更不能触及其他站点、Nginx 或 SSL。WP-CLI 使用与 WP Box 相同的 `wordpress:cli-2.12.0-php8.3` 固定摘要镜像和 `web_default` 网络；在确认前检测或拉取并缓存镜像，验证容器启动及目标数据库只读连接。每次命令均使用 `docker run --rm`，只挂载已验证的目标 WordPress Root，以该 Root 的非 root 属主运行，并显式执行 `wp`；路径或属主无法安全验证时立即停止。

总体进度采用预定义安全节点，只在对应节点真实完成后单调增加。两层归档解压分别计入完成节点；复制、数据库导入和 WP-CLI 等无法从现有工具稳定取得内部比例的步骤，在命令成功返回后更新，不按耗时推算。失败不会补齐进度，100% 仅代表文件、数据库、域名处理、Elementor、固定链接和最终配置检查全部成功。

更换域名模式按 HTTPS、HTTP、协议相对 URL 和具有域名边界的裸域名顺序执行，每组替换均先 dry-run，再用相同参数正式执行；固定使用 `--all-tables-with-prefix --skip-columns=guid --precise`。保留域名模式不执行全库域名替换。Elementor 命令按实际安装、启用状态和命令帮助发现结果执行，加载范围限制为 Elementor/Elementor Pro，并使用已验证的下划线命令 `replace_urls` 和 `flush_css --regenerate`。

站点导入只支持空白目标数据库的一次性完整流程。写入后任何步骤失败都报告部分完成状态；用户需重新准备空白目标站点后从头导入。

正式执行确认页必须显示导入模式、目标网址、当前主机名与 CPU/内存展示信息、目标 WordPress Root、目标数据库名称及备份文件；后台仍保留完整服务器身份锁和复核。只有用户输入完整的 `yes` 才能继续；错误内容允许重试，直接回车取消，输入 `0` 返回上一级。确认后仍需再次验证目标身份。若数据库或文件写入失败，会记录已完成步骤并提示可能的部分导入状态，不自动回滚。

## 测试约束

迁移测试必须覆盖多站点共存、相似域名、同域名不同服务器身份、不同表前缀、配置变化和目标身份不一致。所有异常都应在写入前停止，并验证旁站内容保持不变。
